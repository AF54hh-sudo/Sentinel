# Architecture

Phase 2 contains a deterministic generator, canonical table contract, CSV persistence, and validation boundary. The generator creates related business facts; validation checks schema, keys, foreign keys, numeric ranges, and accounting identities.

Phase 3 adds one local PostgreSQL database accessed through SQLAlchemy and Psycopg. Five normalized business tables enforce primary keys, foreign keys, allowed categories, ranges, date relationships, and accounting reconciliations. A transactional loader validates CSVs before insertion, protects non-empty tables unless replacement is explicit, and verifies row counts and orphan counts afterward. No application or AI layer is present.

Phase 5 adds predefined SQLAlchemy Core analytics above the database boundary. A validated immutable filter contract binds inclusive dates, regions, and plans. Query functions aggregate revenue, costs, contribution, subscription outcomes, support, trends, and approved dimensions. Live tests reconcile PostgreSQL aggregates against independent Pandas calculations. Arbitrary business-question-to-SQL generation remains out of scope.

Phase 6 adds a statistical inference layer over cleaned database extracts. Customer-level pre-outcome support features feed Welch and Mann-Whitney comparisons plus Pearson/Spearman sensitivity analyses. Subscription frequencies feed chi-square tests. A typed report contract carries hypotheses, rationale, samples, statistics, p-values, effect sizes, assumptions, interpretations, and limitations. No ML model is trained in this layer.

Phase 7 adds a supervised churn layer. A point-in-time feature builder converts normalized customer, subscription, sales, and support facts into one row per eligible customer without future information. Reusable Scikit-learn preprocessing and classifier pipelines feed stratified cross-validation, moderate randomized tuning, out-of-fold threshold selection, held-out evaluation, error analysis, and permutation importance. The training runner persists a versioned artifact containing the full preprocessing/model pipeline, operating threshold, feature contract, snapshot definition, and AMX Tech ownership metadata. The application layer remains absent.

Phase 8 adds a retrospective cloud-cost anomaly layer. Regional facts are reconciled and summed to a complete daily company series. A centered robust local median adjusts for level changes, standard and outer IQR fences provide a transparent baseline, and Isolation Forest supplies a model-based score. Final strong anomalies require conservative agreement between the outer fence and Isolation Forest. Evaluation-only scenario dates are supplied to a separate scoring function after detection and are never imported by the detector. Versioned detector metadata, full daily scores, and an audit report are persisted for later visualization and application use.

Phase 9 adds a chronological monthly net-revenue forecasting layer. Sales are aggregated to a complete month-start series, then naïve, three-month moving-average, and additive damped-trend exponential-smoothing methods are evaluated with expanding-window one-step forecasts. Method selection uses validation WAPE only; the chosen method is fixed before the later test period is scored. The selected model is refit on all observed months and persisted with its forecast contract, backtest rows, and machine-readable report. No random time-series split or future observation enters an earlier forecast.

Phase 10 adds a presentation-only Plotly layer above the validated analytical outputs. Chart functions accept explicit DataFrame, Series, or report contracts and return reusable `go.Figure` objects without querying data, fitting models, or changing business metrics. A gallery runner composes EDA aggregates and persisted Phase 7–9 evidence into standalone HTML views for review. The same functions are ready for the Phase 11 Streamlit interface, keeping calculations in their owning analytical modules.

Phase 11 adds a local Streamlit application above that presentation layer. A dedicated dashboard data boundary loads CSV or PostgreSQL business tables, applies the established cleaning and validation policy, verifies Phase 7–9 artifacts, and produces filter-aware analytical views. Streamlit controls composition and display only: calculations remain in reusable Pandas, forecasting, anomaly, ML-report, and Plotly modules. Company-wide forecast and anomaly evidence is not silently filtered by dimensions those artifacts do not contain. The entry point has no LLM, RAG, LangGraph, notebook, or ground-truth dependency.

Phase 12 adds a narrow hosted-LLM boundary for question understanding. Streamlit or the CLI supplies a free-form question plus trusted dataset dates and allowlisted dimensions. An OpenAI Responses client requests a strict Pydantic structured output and returns an intent, metrics, time range, filters, analysis mode, clarification state, and confidence. Provider credentials and model are environment-configured; errors are normalized without logging secrets or question content. No tools, business rows, SQL execution, calculations, LangGraph, RAG, or ground-truth context are available to the LLM in this phase.

Phase 13 adds a compiled LangGraph `StateGraph` with fixed nodes and conditional routing. The path is question understanding, deterministic planning, exactly one approved analytical branch, and evidence validation. Branches wrap existing business analytics, statistical reports, held-out churn predictions, revenue forecasts, anomaly scores, and cleaning validation. The model cannot define a plan, select arbitrary functions, generate SQL, or execute code. Unsupported grains and ambiguous intent terminate before analysis; RAG remains absent from this graph.

Phase 14 adds a separate internal-document retrieval subsystem without changing that analytical graph. Ten fictional AMX Tech Markdown records pass through validated metadata extraction, deterministic heading/paragraph chunking, stable citation IDs, injected OpenAI embeddings, and a fixed-dimension PostgreSQL `document_chunks` table backed by pgvector. Question embeddings drive exact cosine search and return typed source metadata, text, similarity, and business relevance. The Streamlit Documents tab and CLI expose retrieval independently.

Phase 16 composes the completed layers into one guided Streamlit investigation. A four-stage progress model connects question understanding, bounded analysis, optional document retrieval, and evidence reporting; branch-appropriate Plotly views expose the analytical evidence inline. Capability readiness, isolated error states, and resettable session state keep optional hosted services from obscuring the fully local explorer. This is a presentation and interaction layer only: analytical ownership, evidence validation, and service boundaries remain unchanged.

Phase 17 establishes an enforced branch-aware coverage floor and verifies the seams between those layers. The default suite uses deterministic generated data and injected hosted-service fakes; live PostgreSQL, SQL/Pandas reconciliation, and pgvector checks remain clearly marked optional integrations. Streamlit's native test renderer verifies rerun and session-state behavior, while runtime health checks verify the served application independently.

Phase 15 adds a reporting layer after the analytical graph. One verified analytical result and up to five retrieved chunks enter a typed immutable registry with deterministic evidence IDs. A deterministic fallback or injected OpenAI Structured Outputs client authors only cited narrative claims; local validation rejects unknown evidence, unsupported numbers, document-only findings, and positive causal language. Key metrics, document references, qualitative confidence, inherited limitations, and Markdown formatting remain deterministic. The report layer neither changes calculations nor grants the model tools.
